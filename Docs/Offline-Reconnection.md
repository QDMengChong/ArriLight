# 离线设备自动重连

应用级单例 `DeviceReconnectQueue` 统一调度 AGP / Mesh 已保存设备的恢复。
首页、控制页和手动重试继续观察、加入现有运行时准备任务。连接直接使用保存的
MAC / UUID，不增加独立扫描、心跳或离线判断，也不修改监督超时。

## 调度

- 地址忽略大小写去重；同一地址只执行一次建连，调用者取消等待不撤销共享任务。
- 没有设备时不建连；单台设备每次开始至少间隔 2000ms；多台最多两个建连槽。
- 自动建连开始至少错开 1000ms，每个槽两次开始至少间隔 2000ms。
- 失败设备重新加入队尾；五台、十台设备在快速失败的理想条件下，约每五秒、十秒轮转一次。
- 槽持续占用到原生调用与取消清理结束，不因期限到达提前释放，也不补发积压次数。
- 建连成功即释放建连槽；响应通道、认证、通知和资料准备继续复用原运行时任务。
- 用户请求优先，OTA / 配对沿用目标设备独占屏障；删除设备移除恢复登记。
- 后台 / 关闭取消应用生命周期内的工作；回到前台重新登记。蓝牙或权限不可用时
  只检查恢复条件，不发起原生建连，也不弹出自动权限请求。
- 每两秒由同一个应用级计时器检查未完成的准备工作；已就绪设备不会因此读状态或重连。

## 超时与调试

现有调试配置页的 `appsettings.json` 可设置：

```json
"Reconnect": {
  "ConnectionTimeoutMilliseconds": 1200
}
```

默认 **1200ms**，允许 100–30000ms；配置缺失时同样使用 1200ms。
保存后下一次离线自动重试 / 断线恢复读取配置。它只限制这两类请求的单次蓝牙建连，
权限、队列等待、配置读取不计入这项期限。

应用启动、回到前台的首轮连接、页面连接 / 手动重试、控制操作隐式连接、配对和 OTA
继续使用原有的超时，不读取这项参数。启动或前台首轮失败后，后台调度器再发起的
离线重试才使用 1200ms。手动请求加入正在执行的自动恢复时，复用同一个连接任务，
取消其自动恢复短期限，保留原有普通连接期限；不另发一次连接。

普通 AGP 连接步骤保留 20 秒，会话准备保留 40 秒；响应通道和认证步骤保留 10 秒，
Mesh 会话保留 20 秒，配对保留独立的 3 秒窗口。资料读取和控制操作的既有期限不变。

现有 `Connection.ConnectCore`、`Connection.NativeConnect`、`Connection.FindDevice`
诊断时间记录用于检查成功、失败、取消与设备地址；队列等待不计入建连记录。

缺少 Token 或明确认证拒绝后，等待 Token 变化；补读资料只重试失败 / 未完成步骤，
保留成功资料与认证会话。连接恢复不保存或重放控制指令。

## 验证

自动化测试覆盖单台节奏、两槽错峰、五台 / 十台公平顺序、超时后清理占槽、
共享任务、用户优先、权限恢复、长期失败持续重试、后台暂停与认证 / 资料恢复。
真机仍需验证首次 / 再次连接、两个任务错峰、设备长时间关机，以及原生取消清理，
评估 1200ms 的实际成功率与取消清理稳定性。
