# ArriLight 全局设备状态实施路径

日期：2026-10-08。依据 [设计提案](DeviceRuntime-State-Design.md)，本次实现按以下顺序推进，保留已有 Toggle、排序和添加页扫描改动。

## 实施顺序

1. 建立设备运行快照、资料步骤及执行结果模型。加入共享调度队列，默认最多五台设备同时推进，可设置一至五台；同一设备串行执行，用户操作优先于普通查询。
2. 拆分 AGP 最小准备和资料读取。使用本地能力决定认证及读取清单，连接和响应订阅完成后按需认证，立即发布在线；随后分步取得灯状态、模式、延时、颜色、时钟、日程和设备信息。
3. 将原生 GATT 的操作锁按设备划分，保留连接代次、断开清理和 OTA 独占约束。响应通道、灯状态订阅和颜色订阅分别建立。
4. 将启动、恢复、后台、退出、异常断开和删除同步到全局集合。页面取消只结束页面等待，共享准备和已提交用户操作由应用生命周期管理。
5. 接入列表的离线、在线、就绪及准备阶段，控制页复用共享资料，设置页提供并发数选择。
6. 运行顺序、抢占边界、能力缓存、并发预算、失败保留会话和生命周期回归，运行已有测试及 Android 构建；记录实际结果与需要真机验证的边界。

## 验证重点

- 已保存能力不重复读取；缺失能力仅补读一次。
- 认证成功即在线，资料完成才就绪；查询失败保留在线和认证。
- 点击翻转不取消目标连接或认证，等待当前查询完成后优先执行一次。
- 多设备并行受预算限制，离线设备不阻塞其他设备；后续关键准备优先于长资料查询。
- 页面跳转不撤销共享任务，后台使全部记录立即不可操作，迟到回调不会恢复旧会话。
- 已发送翻转结果未知时不自动重放；所有准备、连接和重试均不启动扫描。

上述路径已完成。实现与验证结果见 [DeviceRuntime-Implementation-Results.md](DeviceRuntime-Implementation-Results.md)。
