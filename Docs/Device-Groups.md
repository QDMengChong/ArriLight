# App 设备分组

设备分组是本机 App 的逻辑成员关系，独立于设备清单及 Mesh 网络的订阅分组。组记录不包含设备 Token，不参与蓝牙连接身份。允许同一设备属于多个组；所有入口仍共用设备本身的操作队列和真实状态。

## 使用入口

1. 在设备首页的“设备分组”区域点击“创建分组”，填写名称。
2. 从已保存的设备中添加成员。设备能力需要已确认；演示设备只能与演示设备分组。
3. 在成员管理中上移、下移、移出设备，第一台标注为“参考设备”。“控制分组”进入控制页。
4. 控制页按参考设备能力显示开关、亮度、颜色、色温、特效、倒计时、本地按键模式。页面右上角可再次进入成员管理。
5. 组预设最多 6 个。自动关灯、特效周期、倒计时默认秒数保存在组中；可单独点击保存。

组功能以参考设备为准，添加成员需支持全部组控制功能；亮度的 8/16 位传输差异不构成功能不兼容。电量、认证、设备信息、日程和升级不参与组控制能力比较。色温成员需覆盖参考设备的色温范围。重新排序若会让新参考设备的功能超出其他成员能力，会提示不兼容并保留原顺序。

移出或删除组不解除设备绑定。从 App 删除真实设备后，其在所有组中的引用自动清除。移出参考设备后下一台接替；若新参考设备能力更广，现有不兼容成员会明确标识并跳过控制，允许继续整理成员。空组保留管理入口。

## 控制与状态

- 每次新进入控制页从参考设备缓存初始化；离线参考设备标明最后已知状态，无开关状态时显示未知。进入页面不会自动把参考设备的状态写到其他设备。
- 用户操作后，组界面显示目标值，提交完成即反馈“已提交至 N 台，跳过 M 台”。不等待全员响应，不因某台失败回滚。成员的通知、响应只更新成员实际状态和结果。
- 参考设备暂时离线或锁定不阻止其他可控制成员。排序更换参考设备后重新初始化组界面；从管理页返回同一参考设备时保留当前输入。
- 仅捕获提交时已经连接且已完成认证/控制通道准备的成员。锁定、升级独占、能力不兼容或无有效控制会话的成员跳过。
- 执行前再次验证原连接代次与成员关系。移出后重新加入、组删除、连接断开或重建都不能让旧操作再次执行。设备自身的正常自动重连仍继续，旧组操作不会跟随重连补发。
- 开关发送统一绝对值，不发送 Toggle。每台设备内保持操作顺序，跨设备通过现有调度器并发执行；无法保证各灯在完全相同的物理时刻变化。
- 滑块有 250 ms 防抖，新的灯光设置取代同组尚未执行的旧灯光设置。已发送的请求继续处理响应，开关和组合操作保留必要顺序。
- 特效及自动关灯按每台设备内部的批次依次执行，例如“特效 → 开灯 → 自动关灯”。某一步失败保留设备已确认完成的步骤。
- 页面离开只取消尚未提交的滑块输入。已提交的设备操作由应用运行时持有，应用进入后台/关闭时遵循现有取消与清理机制。

定时日程暂不提供组入口，避免覆盖各设备已有槽位。升级、分享、解除绑定保留在单设备详情中。组配置及预设不写入参考设备的本地个人配置。

## 验证与真机调试

自动回归通过可控队列与 fake GATT 覆盖持久化、成员清理、能力/色温兼容、并发提交、失败隔离、旧连接及旧成员失效、滑块合并、通知隔离、绝对开关和特效批次。命令：

```powershell
dotnet test tests/ArriLight.Tests/ArriLight.Tests.csproj --filter FullyQualifiedName~DeviceGroup
```

建议使用两台或以上设备验证：

1. 两台设备分别处于开/关状态，打开组查看参考设备的初始显示，再点击统一开或统一关。
2. 单独操作成员或硬件按键，检查成员列表变化，而组目标值保持。
3. 参考设备离线、另一台在线时群控，确认不会因参考设备离线阻塞。
4. 一台锁定或断线时操作，随后解锁/重连，确认不会补执行旧操作。
5. 连续拖动亮度/颜色后关灯，检查最终参数与指令顺序。
6. 调整参考设备、移出成员、删除组、删除真实设备，检查成员引用和设备记录。
7. 组内设置特效及自动关灯，检查各设备实际动作与错误状态；保存组预设后检查单设备原有预设和默认参数。
8. 在小屏和深色主题下检查两个新页面的滚动、成员按钮和色温滑块。

演示设备支持模拟组即时状态更新，计时与硬件动作仍需真机验证。软件测试与平台编译不替代手机蓝牙并发数量、无线时序及页面实际触摸验证。
