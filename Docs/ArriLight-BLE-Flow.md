# ArriLight BLE 流程说明

本文档说明当前 ArriLight APP 的 BLE 扫描、连接、主页状态查询、设备控制和绑定流程。

## 1. 服务边界

ArriLight 只负责 APP 层的页面和调度。BLE 协议实现位于 `ArriOpto.BLE`，PW01 固件不在本项目修改范围内。

主要服务注册在 `MauiProgram.cs`，其中 `BluetoothDiscoveryService`、`BluetoothConnectionService`、`AgpLightControlService` 和 `DeviceRepository` 均为单例。

当前 APP 仍然只维护一条活动 BLE GATT 会话。后台扫描可以与主页的一台设备状态查询同时存在，但不支持多台 PW01 同时建立独立 GATT 控制会话。

## 2. 后台扫描流程

扫描由 `BluetoothDiscoveryService` 统一管理，页面只订阅 `DeviceFound` 事件。

### 主页

1. `MainPage.OnAppearing` 重新加载本地设备列表。
2. 清空本次主页扫描的状态查询队列和已查询集合。
3. 订阅 `BluetoothDiscoveryService.DeviceFound`。
4. 启动或重置 60 秒低延迟、主动匹配 BLE 扫描。
5. 扫描收到广播后更新设备缓存，并向订阅页面发布 `DiscoveredBluetoothDevice`。
6. `MainPage` 只关注“已保存在我的设备列表中、且不是演示设备”的广播设备。

主页离开时取消页面的状态查询、取消事件订阅，并停止服务级扫描。进入添加页时会重新启动并重置 60 秒窗口。

### 添加页面

添加页面进入时启动或重置 60 秒扫描并订阅广播事件。页面离开时只取消本页面的等待，不主动停止服务级扫描，因此其他页面仍可以继续使用扫描结果。

用户选择设备进行添加时，添加页面会显式停止扫描，然后执行命名和绑定流程。配对提示根据实际进度显示连接、等待重试或获取配对信息，并保留 60 秒倒计时与取消操作。

### 控制页面

控制页面进入时先等待后台扫描停止，再执行连接、能力读取和控制操作，避免后台扫描影响当前设备的 GATT 操作。

## 3. 设备连接流程

设备连接入口主要是 `BluetoothConnectionService.ConnectAsync`，调用链如下：

```text
页面或 AGP 服务
    ↓
BluetoothConnectionService.ConnectAsync
    ↓
BluetoothDiscoveryService.FindDeviceAsync
    ↓
扫描缓存命中，或等待后台扫描收到目标广播
    ↓
Plugin.BLE 连接 IDevice
    ↓
获取 GATT Service/Characteristic
    ↓
AgpGattTransport
    ↓
ArriOpto.BLE.Agp AgpClient
```

如果扫描缓存中已有设备，连接流程不会重新扫描；如果没有缓存，`FindDeviceAsync` 会监听当前后台扫描，等待目标设备广播，不会停止正在运行的全量扫描。

`BluetoothConnectionService` 使用一个连接锁和一个当前设备对象，因此同一时刻只允许一个活动 GATT 设备。切换设备时，需要先清理通知并断开当前设备。

## 4. 主页状态查询流程

主页状态查询由 BLE 广播触发，而不是打开主页后直接遍历所有已保存设备。

1. 扫描收到一个广播。
2. 主页按地址查找本地“我的设备”列表。
3. 未保存设备和演示设备不会进入查询队列。
4. 已保存设备进入待查询队列，并记录 RSSI。
5. 等待约 200 ms 收集同一批广播。
6. 按 RSSI 从强到弱排序，信号强的设备优先查询。
7. 每台设备在本次主页扫描窗口内只查询一次，不再进行第二遍重试。
8. 查询超时时间为 5 秒。

查询调用 `AgpLightControlService.GetOnOffStateWithoutAuthorizationAsync`，流程如下：

```text
获取 AGP 操作锁
    ↓
清理旧的 AGP 会话
    ↓
连接目标 PW01
    ↓
读取公开 Light State 特征
    ↓
解码开关状态
    ↓
更新主页设备状态
    ↓
释放 AGP 会话并断开 BLE
```

主页查询不读取能力位、不获取 Token、不执行 AGP 授权，因此不会弹出绑定确认窗口。

成功读取的完整 Light State（开关、亮度和模式等）按设备地址缓存在 `AgpLightControlService`，只在本次 APP 运行期间保留。控制会话收到状态通知或成功执行开关/特效指令时，也会更新已知状态；主页重新加载列表时恢复这些结果。超时/失败记录离线，取消或尚未完成的查询不发布新结果。

5 秒超时覆盖连接、GATT 服务发现和公开状态读取的整个过程。超时或其他异常会把设备标记为离线；用户操作到来时，后台查询会被取消并让出 AGP 操作锁。

## 5. 设备控制流程

用户从主页进入真实设备控制页时，主页不会等待连接完成，而是立即导航。控制页进入后执行：

1. 停止后台扫描。
2. 如果已有成功查询结果，先恢复开关和亮度显示。
3. 连接目标设备。
4. 读取 AGP 能力位。
5. 如果设备支持安全控制，读取本地 Token 并执行认证；没有 Token 时提示尚未绑定，用户需从添加页面完成配对。
6. 成功查询过的 Light State 直接复用；没有可用结果时读取一次。仍读取 Color State、CTL 范围及特效参数等控制页所需数据。
7. 根据能力位显示亮度、HSL、CTL 或组合控制界面。

进入控制页仍建立实际 BLE 连接并认证；缓存灯状态不能跳过 Token 校验，也不代表 BLE 连接仍存在。控制页直接使用控制 Profile 携带的 Light State，不再额外调用开关状态查询。顶部设备设置按钮左侧新增“刷新”，强制读取一次新的 Light State，同时更新控制 Profile 和共享缓存；已建立的授权连接可继续复用，断开后则重新连接并认证。刷新进行中按钮不可重复点击，离开页面取消未完成的初始化或刷新；返回时等待旧的取消流程结束后再初始化。

控制指令通过 `AgpLightControlService` 串行发送，例如开关、亮度、HSL、CTL、定时和计划任务。控制页复用当前 AGP 会话，用户离开页面后由连接服务和页面生命周期负责清理。

控制页的“定时设置”和计时区域在取得能力前默认隐藏。“定时设置”仅在设备声明 `RtcTime` 时显示；计时区域仅在设备声明 `RelativeTimer (0x80)` 时显示，并同时提供“计时关灯”和“计时开灯”，不依赖 RTC/Scheduler。计时关灯发送 `DELAY_OFF_SET (0x0201)`，计时开灯发送 `DELAY_ON_SET (0x0203)`，负载均为 4 字节小端秒数；服务允许 0 秒取消当前相对计时，页面输入仍为 1～86400 秒。延时开灯不占用日程槽，8 个日程槽均可用于日程设置。隐藏区域不响应发送或跳转操作。PW01 当前能力值 `0xA287` 无 RTC/Scheduler，显示两种计时选项，隐藏定时设置。

每次读取 AGP Capabilities 特征时，`BluetoothConnectionService` 会输出 `[AGP/Capabilities]` 诊断日志，包含设备地址、实际读取的特征 UUID、完整原始十六进制字节，以及按协议解析的 64 位能力值（固定 16 位十六进制）、能力名称和 `effectsSupported`。解析失败时仍保留原始数据日志，并记录失败原因；诊断解析不改变读取结果或客户端的协议错误处理。Debug 构建始终在 Visual Studio“输出 → 调试”中显示这些日志；隐藏调试开关只控制文件写入。

特效参数入口为长按“闪烁”或“呼吸灯”按钮约 650 ms；常亮、提示文字和卡片空白不打开参数设置。Android 使用与配对提示相同的原生居中圆角 Dialog，将整个应用背景变暗；其他平台或无法取得 Android Activity 时使用页内居中遮罩。设置不执行页面导航，因此保留控制页与 BLE 会话。周期范围为 200～10000 ms，按 100 ms 调整，点击“应用”才提交参数；取消、返回键、断连或离开页面均收起对话框并结束等待。对话框适配浅色/深色主题，长按触发、打开成功及异常记录在 `[Light/EffectSettings]` 日志中，异常同时显示重试提示。

特效卡片只保留标题、右侧“长按设置/查看参数”提示和模式按钮；当前周期在对应的设置对话框中查看。闪烁和呼吸灯分别使用独立的参数模型与设置入口，当前均包含周期，后续可各自增加不同参数。参数随设备记录分别保存，切换模式或重新进入页面时恢复对应值；设备返回的状态只更新该模式的参数，常亮不覆盖其他模式。长按、应用和取消均保留当前选中特效：编辑未选中特效时，“应用”只保存本机参数；编辑当前特效时，“应用”发送同一模式的新参数并在成功后保存。短按模式按钮才切换特效并发送对应参数；PW01 成功切换到闪烁或呼吸灯时会先开启灯，控制页同步将总开关按钮更新为“关闭”（表示当前可点击关闭），共享灯状态也记录为开启。常亮模式不会因特效切换额外改变总开关状态。取消或发送失败不覆盖已保存参数。

自定义配置栏仅在设备支持亮度、色温、灯光颜色或特效中的至少一项时显示；特效按钮与亮度/颜色控制共用同一个灯光调节卡片。每个配置项按颜色预览、名称、简短描述三行显示。保存时只记录设备支持的设置：闪烁或呼吸灯时描述特效名称，常亮按无特效处理，否则按亮度/色温显示一个或两个百分比；两者都没有时显示颜色的 RGB 十六进制值。没有明确灯光颜色时，颜色预览使用色温到 RGB 的近似换算并结合亮度生成。恢复同时包含灯光设置和动态特效的配置时，先发送亮度/颜色设置，再发送特效指令，避免后续灯光模型写入覆盖特效。

自定义配置按设备地址写入本地设备记录，保存、删除和拖动排序后立即更新；重新进入控制页或重启应用会恢复对应设备的配置，删除设备时一并清理。计时开灯/关灯的输入框默认 60 秒，修改后的有效秒数也按设备立即保存，无需发送计时指令，下次打开控制页恢复该值。

## 6. 用户操作与后台任务优先级

当前优先级如下：

```text
用户灯控/授权
    >
进入设备控制页
    >
主页单台状态查询
    >
后台 BLE 广播扫描
```

当用户点击开关、进入控制页或离开主页时，主页会取消正在进行的状态查询。控制页会先停止扫描，再执行连接和控制操作。

## 7. 配对与多个 APP 依次绑定

PW01 同时只支持一条 BLE 连接。用户双键长按 1 秒打开约 60 秒的物理配对窗口后，多个 APP 可在剩余窗口内依次获取 Token；每次配对结束不延长硬件窗口。

`AgpLightControlService.BindAsync` 使用独立的配对流程：

1. 显示“正在连接 PW01”，启动 60 秒等待上限。
2. 按 500 ms 间隔串行尝试连接。单次连接等待最多 500 ms；无响应时取消本轮原生连接后再尝试，避免长时间卡在系统连接调用中。立即失败时等待本轮剩余时间，不并发建立连接。
3. 连接暂时不可用时显示“设备可能正被其他手机占用，正在等待并自动重试”。BLE 连接错误无法单独证明占用，因此提示保留“可能”。用户取消、离开页面或等待超时均停止重试。
4. 连接成功后显示“已连接，正在获取配对信息”。只开启 Control Point Indicate，读取能力位以确认支持 Token 配对，再发送 `AUTH_GET_TOKEN`。
5. 检查成功结果及四字节 Token，保存到本地设备记录。ATT Indication 接收确认由手机 BLE 栈自动完成，不新增 AGP 确认命令。
6. Token 保存成功即配对完成，关闭配对提示框并显示“添加成功”，继续停留在“添加设备”页面，不自动返回主页。不在配对连接上继续执行 `AUTH_TOKEN`、读取/订阅灯状态或校时；PW01 的预期主动断开不会把配对结果改为失败。连接清理失败也不删除已保存的 Token。
7. 后续控制操作重新连接、启用通知、用保存的 Token 认证，然后读取状态并按能力校时。

本地配对凭据是设备地址和 Token，设备名称、添加时间等属于列表信息。`Light State` 的开关、亮度、过渡、模式、状态标志和状态版本号只服务于运行状态与控制，不参与配对持久化。

重试仅覆盖建连阶段。蓝牙权限等发现错误、连接成功后的协议拒绝、无效 Token 或保存失败直接结束本次配对；窗口已关闭时提示重新开启窗口，避免不断重连占用唯一连接。Android 原生 Dialog 与其他平台的页面遮罩使用相同阶段文案，倒计时不会覆盖阶段提示。

提示框和倒计时由添加页面管理。倒计时使用页面自己的取消令牌，不能使用配对服务内部的关联令牌：服务完成并释放关联令牌源后，页面取消无法再传递给它。配对结束先停止倒计时并关闭提示框，再等待倒计时任务收尾；取消按钮和页面离开直接关闭原生 Dialog/页面遮罩，已经取消的倒计时不会继续更新界面。

配对服务回归测试在仓库根目录运行：

```powershell
dotnet test tests\ArriLight.Tests\ArriLight.Tests.csproj
```

测试直接编译应用的配对、连接、GATT 适配器、设备持久化及添加页面源文件，复用 `ArriOpto.BLE` 客户端与编解码器；替换无线接口、发现、平台存储/日志和 MAUI 界面边界。覆盖 Token 后立即断开、500 ms 重试、原生连接无响应、取消/超时、窗口拒绝、无效 Token、清理失败、后续控制重连，以及成功后立即关闭提示框、服务令牌源释放后的倒计时取消、取消/离开页面关闭提示。页面测试不渲染 Android 原生 Dialog；它不替代多个手机与 PW01 样机的无线验证，尤其应验证 500 ms 连接尝试在目标手机上的成功率。

特效对话框回归测试也使用上述 `dotnet test` 命令，直接编译 `DeviceControlPage.EffectSettings.cs` 的对话框控制逻辑与设备参数持久化，替换 UI 与灯控发送边界。覆盖当前特效应用后更新周期并保留选择、未选中特效应用仅保存参数、取消后保留参数与选择、重开、返回键/断连/离开页面关闭并结束等待、重复打开和不可用状态，以及两种特效参数独立、切换和重进页面恢复、设备之间隔离、状态读取只更新当前模式与发送失败不覆盖参数。测试不渲染 Android 原生窗口，仍需在手机上复测滑块拖动、背景变暗、返回键与主题配色。

状态复用回归测试验证主页只读取公开 Light State 并断开、按地址复用完整结果、进入控制会话仍需连接和认证、无结果时只读取一次、刷新已有连接或断开连接时都只新增一次读取、刷新优先于缓存、Token 拒绝不能被缓存绕过，以及取消查询不发布结果、离线记录不复用为在线和控制指令更新共享状态。

Relative Timer 回归测试验证无 RTC/Scheduler 时仍可发送延时开/关灯、对应 opcode 与 4 字节小端秒数、0 秒取消、30 天上限、非整秒向上取整、缺少 `RelativeTimer` 时拒绝，以及业务失败不会因 GATT 写成功而被当作成功。协议库另有 `DELAY_ON_SET/GET` 精确规范向量及响应格式校验测试。

## 8. 重要限制

- 当前只支持一条活动 GATT 会话，不支持多台 PW01 同时控制。
- BLE 广播只能说明设备可能可达，不能直接表示灯的真实开关状态；真实状态仍需 GATT 读取。
- 扫描缓存是短期连接优化，不等于设备当前一定在线。
- 主页状态查询是一次性查询；设备在本次扫描窗口内再次广播不会重复查询。
- Android 手机和 BLE 芯片对“扫描 + GATT 连接”并行的稳定性可能不同，实际发布前应在目标手机上验证连接超时和 GATT 133 错误。
