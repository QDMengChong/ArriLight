# ArriLight BLE 流程说明

本文档说明当前 ArriLight APP 的 BLE 扫描、连接、主页状态查询、设备控制和绑定流程。

## 1. 服务边界

ArriLight 只负责 APP 层的页面和调度。BLE 协议实现位于 `ArriOpto.BLE`，PW01 固件不在本项目修改范围内。

业务状态与命令已迁入 ViewModel，页面保留首帧、动画和原生控件调度，详见 [MVVM 分层](MVVM.md)。

主要服务注册在 `MauiProgram.cs`，其中 `BluetoothDiscoveryService`、`BluetoothConnectionService`、`AgpLightControlService` 和 `DeviceRepository` 均为单例。

APP 按设备地址维护独立 BLE 会话、通知、认证和全局运行快照。2026-10-08 已接入 [全局设备状态设计](DeviceRuntime-State-Design.md)，实际代码与验证见 [实施结果](DeviceRuntime-Implementation-Results.md)。Window.Created 开始准备所有已保存真实设备，默认同时推进五台，设置页可选一至五台；同设备串行，不同设备按预算并行，原生 GATT 锁也按地址划分。

连接、响应通道及按需认证完成即发布在线，可以发送 Toggle；本轮全部适用资料完成后才就绪。普通资料失败保留在线及认证，缺失资料可继续补齐。页面跳转只改变订阅和等待，不释放共享准备及已提交用户操作。前台运行时保留准备完成的会话；旧公开查询与短租约接口仅作为兼容路径保留，正常启动由全局集合管理。

断开处理按地址和原因区分：正常释放、短时租约到期和前后台切换只保留目标的扫描定位缓存；删除设备、主页查询失败和异常断开会调用 `InvalidateCachedDevice` 清除目标缓存。所有断开路径都会取消目标通知并丢弃旧的特征与 GATT 会话对象，其他设备会话不受影响；后续操作只复用扫描定位结果并重新建立连接会话，不复用已经关闭的 GATT 对象。认证客户端记录建立时的连接代次，断开重连后必须重新认证。

## 2. 添加页扫描与主页排序（2026-10-08）

扫描由 `BluetoothDiscoveryService` 执行，只能从添加设备页启动，其取消令牌同时控制原生扫描。

### 主页

1. `MainPage.OnAppearing` 转发到 `MainPageViewModel.OnAppearingAsync`，重新加载本地设备列表。
2. 显示已有状态缓存，订阅控制会话的状态更新，不启动广播扫描或公开状态轮询。
3. 右侧 Picker 选择按上次操作时间、加入时间或名字排序，默认最近操作优先，并保存选择。
4. 时间排序最近优先，名字按当前文化升序；全部方式都先显示置顶设备。未操作设备按加入时间排序。
5. 成功控制后保存 `LastOperatedAt` 并重排；已有设备行保留其忙碌状态，防止重排后重复发送。

主页离开时解除状态订阅。开关在未知或离线状态仍可点击，操作期间禁用同一设备的重复点击。

### 添加页面

添加页面进入时启动 60 秒扫描并订阅广播事件。离开立即取消扫描令牌，原生任务在收尾时停止扫描并解除广播订阅；权限提示迟到返回时先检查令牌，不能在已离开的页面启动扫描。再次进入先等待上一轮收尾，再启动新扫描。APP 后台或关闭窗口也停止扫描。

PW01 的 AGP 广播识别兼容 Android 与 iOS（2026-10-15）：Plugin.BLE 3.2.1 在 Android 上将 128 位服务数据标记为 `ServiceData128Bit`，在 iOS 上将其标记为 `ServiceData`，两者数据均为 AGP UUID 的 BLE 小端字节加格式版本和状态。`AgpAdvertisement` 接受两种类型，并继续严格匹配完整 UUID、格式版本 `0x01` 及已登记状态；添加页仅显示状态为 `PairingOpen=0x01` 的 AGP 设备。修复前 iOS 广播被识别为 Unknown，随后被页面过滤，因此表现为搜索不到 PW01。无需修改固件广播。

实机复测时，在 iPhone 上允许蓝牙访问，使 PW01 进入物理配对窗口（当前固件为正常状态下按住 T1 3～不足 5 秒后松手），确认蓝灯闪烁，再进入添加设备页。应显示 `PhyLight-...`，并可完成添加；关闭配对窗口后重新扫描应不显示该设备。测试两台手机时，先释放上一台手机的连接，PW01 同时仅支持一条 BLE 连接。主机回归覆盖两种广播记录格式及扫描事件，仍需 iPhone 与 PW01 验证实际无线行为。

用户选择设备进行添加时，添加页面会显式停止扫描，然后执行命名和绑定流程。配对提示根据实际进度显示连接、等待重试或获取配对信息，并保留 60 秒倒计时与取消操作。

### 控制页面

支持电量的 AGP 设备在控制页顶部显示“电量”和百分比；未取得读数、设备返回未知值或设备离线时显示“未知”。通过 Battery 能力位或 Battery State 特征判断支持情况，不支持的设备和演示设备隐藏这一行。新固件使用 Battery State Read 初始化并通过 Notify 更新；仅支持 GET 的旧固件在准备或手动刷新时查询。电量读取或订阅失败保留已取得的灯光控制能力。切换设备及重连后重新取得电量，避免沿用其他设备或旧连接的读数。

主页点击设备卡片后立即导航。控制页首帧加载本地配置及共享历史快照，首帧后加入目标的全局准备，并提高正在等待资料的优先级。准备已在启动时运行，不重复建立连接或执行整套查询。页面取消仅结束等待与回调；应用级准备和已提交命令继续推进。

设备卡片除 44×44 的开关区域外均可点击进入控制页，包含图标、名称、状态、留白及箭头。导航点击区域与开关是独立的相邻区域。主页在首次点击同步锁定导航，导航期间或主页隐藏期间的重复点击不再打开其他控制页；返回主页后解除锁定，导航失败则解除锁定并提示重试。

主页到控制页使用 `GoToAsync(..., animate: false)`，关闭 Shell 默认过渡，在控制页导航完成后的 UI 调度中执行 120 ms 的淡入和 14 dp 轻微滑入。首帧后 BLE 准备、LazyView 加载和动画分别启动，彼此不串行等待；ViewModel 接收本次显示的取消令牌并执行扫描清理和 AGP 初始化。Android 系统关闭动画时跳过该过渡；离开页面取消动画并复位透明度和位移，避免返回时残留半透明或偏移状态。演示设备执行同样的短动画，但不执行 BLE 工作。

主页显示约 250 ms 后，在 UI 调度队列中预创建一页常用控制页：存在真实设备时准备普通控制页，否则准备演示控制页。预创建只建立管理界面和初始绑定，不选择设备、不触发页面生命周期、不连接、不认证。路由工厂每种类型最多保存一页未使用的页面；导航消费后立即清空备用引用，下一次进入使用新页面，避免不同设备共享旧页面状态。主页离开、用户开始导航或应用进入后台后，尚未执行的预加载不再创建页面。控制页本地配置复用已经读取的设备记录，保留未变化的配置槽，减少重复反序列化及配置卡片重建。

## 3. 设备连接流程

### 控制页的触摸模式配置

设备信息页不再提供模式配置。控制页的延时卡片移到自定义配置之后、固定隐藏的延时开/关灯卡片之前。卡片第一行保留“延时”复选框、秒数输入和 `s`；第二行依次显示 Switch、模式名称和靠右的“设置”按钮，删除原模式配置的独立秒数输入框，两项功能共用第一行秒数。

`DeviceControlPageViewModel.LocalMode` 在共享初始化的 MODE_GET 步骤完成后使用缓存配置，不等待其他资料全部就绪，也不因进入页面再发送 MODE_GET；LazyView 加载独立进行。仅支持 bit22 `LocalMode` 的真实设备显示模式行；只有 `RelativeTimer` 时保留第一行，只有 `LocalMode` 时仍提供共用秒数但隐藏一次性延时复选框。Switch 开启显示“常亮模式”，关闭显示“延时模式”。秒数默认 60，第一行复选框选中或第二行处于延时模式时可编辑；读取/设置模式期间禁用模式编辑和共用秒数。有效的一次性延时秒数仍按设备保存到手机，模式读取到自动关灯时用设备保存值填充共用秒数；连接或读取期间已经编辑的秒数不会被迟到响应覆盖。

编辑不会发送 BLE 消息；点击设置才分别发送 `AgpModeConfig(DelayNone)` 或 `AgpModeConfig(OnAutoOff, OffSeconds: seconds)`，独立于第一行复选框。模式秒数仍严格为 1～2,592,000 的整数，一次性自动关灯仍为 1～86400 秒，分别在各自操作时校验。配置由 PW01 持久化，重新进入页面以设备值为准，写入失败保留模式和共用秒数草稿。

`MODE_SET=0x0121` 沿用按设备的连接、Token 认证和串行请求调度。`DELAY_NONE` 负载为 `00`；`ON_AUTO_OFF=60s` 负载为 `04 3C 00 00 00`。协议库也支持 `OFF_AUTO_ON`，其参数对应 `OnSeconds`；两种自动模式的编号 4/5 不能当成方向位掩码。页面只提供常亮和自动关灯两个选项，读到其他合法模式时显示提示，等待用户显式设置，不在读取时改写设备。离开页面取消读取等待和页面回调，已提交 MODE_SET 继续执行；应用后台或关闭才取消命令，发送期间禁用编辑和重复设置。

MODE 配置仅作用于硬件直接操作（PW01 的 T1 触摸），与 `Light State.Mode` 的灯效、控制页的一次性自动关灯独立。ON_AUTO_OFF 在触摸开灯或切换亮度时立即执行，再安排自动关灯；重复短按重新计时，触摸关灯立即执行并取消自动动作。MODE_SET 自身不改变灯输出。回归测试覆盖六种模式编解码、自动模式精确报文、边界秒数、能力检查、读取设备保存值、失败保留草稿和页面离开取消。

### 连接调用链

设备连接入口主要是 `BluetoothConnectionService.ConnectAsync`，调用链如下：

```text
页面或 AGP 服务
    ↓
BluetoothConnectionService.ConnectAsync
    ↓
BluetoothDiscoveryService.FindDeviceAsync
    ↓
扫描缓存命中，或按保存的 MAC/UUID 直接连接已知设备
    ↓
Plugin.BLE 连接 IDevice
    ↓
获取 GATT Service/Characteristic
    ↓
AgpGattTransport
    ↓
ArriOpto.BLE.Agp AgpClient
```

缓存未命中时 `FindDeviceAsync` 调用 `ConnectToKnownDeviceAsync`，不等待广播、不启动扫描；Android MAC 转为 Plugin.BLE 的设备 Guid，其他平台使用已保存 UUID。该路径也覆盖冷启动、二维码导入和异常断开后的重连。

`BluetoothConnectionService` 按地址维护连接会话；每个会话独立保存设备对象、通知特征、长连接标记和租约。原生调用锁按设备地址划分，同设备串行且不同设备可以并行。通知携带所属设备地址及连接代次，`AgpGattTransport` 只接受自身目标地址的消息，避免不同 PW01 使用同一特征 UUID 或同一 AGP TID 时串线。页面读取 `GetSnapshot(address)` 并只应用目标地址的连接事件。

## 4. 共享资料与兼容查询接口

正常 APP 运行的状态来自全局准备、控制结果及硬件通知，主页不另建公开查询队列。`QueryDeviceStatusAsync` 在运行集合启用后也加入同设备队列，复用认证会话和安全读取；取消调用方等待不会拆除应用会话。全局运行尚未启用的兼容路径仍保留公开 Light State 查询和旧短租约行为，供已有调用与回归使用。

本地能力有效时不会重复读取 Capabilities。新连接按 SecureControl 要求认证，Token 缺失或拒绝时提示重新绑定，不自动发送 AUTH_GET_TOKEN。Light State、颜色、范围、模式及延时/时钟资料由共享服务缓存，步骤结果判断本轮有效性。后台保留历史值并使步骤失效，不能凭历史资料显示在线或就绪。

有序读取和错误、期限、调度规则以 [实施结果](DeviceRuntime-Implementation-Results.md) 的表格为准。

## 5. 设备控制流程

用户从主页进入真实设备控制页时立即导航，在页面首帧后加入已经运行的全局准备。页面先呈现本地能力和已有资料，按本轮成功步骤应用新灯状态、颜色、范围、特效及本机模式；其他资料失败不阻止使用已经取得的功能。迟到的资料不覆盖用户编辑的模式、秒数、亮度或颜色。

顶部刷新重新安排本轮资料读取，包含新的 Light State；已有连接和认证可继续复用。离开页面取消动画、页面等待与草稿读取回调，共享初始化及已提交控制继续由应用管理。窗口后台或关闭才停止全局任务。

控制指令通过同地址队列插入。Toggle 不要求预先读取灯状态，等待连接/认证或当前查询结束后优先执行；组合指令保持 `ExecuteBatchAsync` 的批量串行语义。不同设备可并行，同一设备只保留一个未完成协议请求。

控制页的“计时关灯”和“计时开灯”区域固定隐藏，也不加载内部 LazyView；暂不提供用户取消隐藏的入口，后续按项目需要调整 `ShowTimedControls`。“定时设置”仍仅在设备声明 `RtcTime` 时显示。服务保留计时开/关灯接口，分别发送 `DELAY_ON_SET (0x0203)` / `DELAY_OFF_SET (0x0201)`，负载均为 4 字节小端秒数，0 秒取消对应计时；不依赖 RTC/Scheduler，也不占用日程槽。

延时卡片位于自定义配置之后、原隐藏计时卡片之前，合并一次性自动关灯与设备触摸模式设置。第一行的复选框仅在设备声明 `RelativeTimer (0x80)` 时显示，默认未选中；共用秒数默认 `60s`。一次性自动关灯范围为 1～86400 秒；未选中且模式行不使用延时时，秒数输入框禁用并置灰。选中状态和有效秒数分别按设备地址写入手机本地记录，重新进入页面或重启 APP 后恢复；独立于原隐藏计时的秒数字段。未选中时控制页开灯和特效保持即时执行，主页开灯不使用该配置。第二行设置设备触摸模式，其生命周期和秒数范围见前文。

主页和控制页电源按钮始终发送 `ONOFF_SET(2)`，由设备依据逻辑开关或渐变目标翻转。认证准备不要求初始 Light State；控制完成优先使用最终 Notify，1 秒内没有通知则读取一次，读取失败不重发翻转。选中延时后，仅在确认设备已开启时发送 `DELAY_OFF_SET(seconds)`；未知结果会提示刷新后设置延时。特效设置（常亮、闪烁、呼吸灯，包括参数应用和配置恢复）仍先发送 `EFFECT_SET(mode, period)`，再显式开灯。发送顺序如下：

| 操作 | 未选中延时 | 选中延时 |
| --- | --- | --- |
| 开关按钮 | `ONOFF_SET(2)` | `ONOFF_SET(2)` → 确认开启后 `DELAY_OFF_SET(seconds)` |
| 特效设置 | `EFFECT_SET` → `ONOFF_SET(1)` | `EFFECT_SET` → `ONOFF_SET(1)` → `DELAY_OFF_SET(seconds)` |

`EFFECT_SET` 与开关已解耦，单独调用服务的 `SetEffectAsync` 只更新特效，不推断或修改电源状态；`ONOFF_SET` 保留当前选中特效。上述组合通过协议库批量串行执行，每一步成功才继续。Busy 由协议库仅重试当前步骤并使用新 TID，其他业务失败、传输失败或取消均停止后续命令，已确认成功的特效和电源状态仍写入共享缓存并反映到界面，不回滚为操作前的状态。

这些操作不使用 `DELAY_ON_SET` 或 APP 延时开灯任务。自动关灯设置成功后由设备计时，离开页面、APP 后台或 BLE 断开不取消计时；应用后台会取消尚未完成的命令组。取消选中复选框只影响后续开灯，不发送计时取消指令。保留原有本地字段名 `TurnOnDelayEnabled` / `TurnOnDelaySeconds`，已有选择和秒数继续用于自动关灯。

每次读取 AGP Capabilities 特征时，`BluetoothConnectionService` 会输出 `[AGP/Capabilities]` 诊断日志，包含设备地址、实际读取的特征 UUID、完整原始十六进制字节，以及按协议解析的 64 位能力值（固定 16 位十六进制）、能力名称和 `effectsSupported`。解析失败时仍保留原始数据日志，并记录失败原因；诊断解析不改变读取结果或客户端的协议错误处理。Debug 构建始终在 Visual Studio“输出 → 调试”中显示这些日志；隐藏调试模式控制文件写入和配置编辑入口。

特效参数入口为长按“闪烁”或“呼吸灯”按钮约 650 ms；常亮、提示文字和卡片空白不打开参数设置。Android 使用与配对提示相同的原生居中圆角 Dialog，将整个应用背景变暗；其他平台或无法取得 Android Activity 时使用页内居中遮罩。设置不执行页面导航，因此保留控制页与 BLE 会话。周期范围为 200～10000 ms，按 100 ms 调整，点击“应用”才提交参数；取消、返回键、断连或离开页面均收起对话框并结束等待。对话框适配浅色/深色主题，长按触发、打开成功及异常记录在 `[Light/EffectSettings]` 日志中，异常同时显示重试提示。

特效卡片只保留标题、右侧“长按设置/查看参数”提示和模式按钮；当前周期在对应的设置对话框中查看。闪烁和呼吸灯分别使用独立的参数模型与设置入口，当前均包含周期，后续可各自增加不同参数。参数随设备记录分别保存，切换模式或重新进入页面时恢复对应值；设备返回的状态只更新该模式的参数，常亮不覆盖其他模式。长按、应用和取消均保留当前选中特效：编辑未选中特效时，“应用”只保存本机参数；编辑当前特效时，“应用”执行同一模式的新参数设置和开灯流程。短按模式按钮切换特效并执行相同流程，常亮、闪烁和呼吸灯均显式发送开灯。成功后总开关按钮更新为“关闭”（表示当前可点击关闭），共享灯状态记录为开启；中途失败按各步骤确认的结果更新，取消编辑或特效步骤失败不覆盖已保存参数。

自定义配置栏仅在设备支持亮度、色温、灯光颜色或特效中的至少一项时显示；特效按钮与亮度/颜色控制共用同一个灯光调节卡片。每个配置项按颜色预览、名称、简短描述三行显示。保存时只记录设备支持的设置：闪烁或呼吸灯时描述特效名称，常亮按无特效处理，否则按亮度/色温显示一个或两个百分比；两者都没有时显示颜色的 RGB 十六进制值。没有明确灯光颜色时，颜色预览使用色温到 RGB 的近似换算并结合亮度生成。恢复同时包含灯光设置和动态特效的配置时，先发送亮度/颜色设置，再发送特效指令，避免后续灯光模型写入覆盖特效。

自定义配置按设备地址写入本地设备记录，保存、删除和拖动排序后立即更新；重新进入控制页或重启应用会恢复对应设备的配置，删除设备时一并清理。原有计时秒数记录保留；新增延时的开关和秒数使用独立字段保存，旧设备记录默认未选中、60 秒。

## 6. 用户操作与应用生命周期

优先级依次为目标独占（删除、OTA、重新绑定）、用户命令及前置条件、其他设备关键准备、页面正在等待的资料、普通资料。每次资料读取和日程槽位完成后释放调度权；用户操作等待在途请求结束再插入，不取消连接和认证。排队取消可及时返回，不等待其他目标的原生工作。

每个用户操作保存唯一 ID 与执行阶段。Toggle 接受后等待完成通知，缺失时读取一次；明确拒绝为失败，无法确认则记未知并提示，绝不自动重放。同设备重复翻转由全局忙碌状态阻止，换页仍有效；初始化读取不更新 LastOperatedAt。

后台和窗口销毁先禁止新工作、使所有设备离线，包括排队、连接和认证中的目标，再取消任务、停止添加页扫描及清理连接。清理失败也保持不可操作。尚未发送的意图取消，已发送而未确认的意图为未知。恢复或新窗口建立新的周期，按预算重新连接、认证和读取；仅重建状态，不恢复旧命令。

生命周期清理与前台恢复通过应用锁协调；连接代次、工作代次、快照版本及取消令牌过滤迟到回调。被替换的旧 Window 事件不影响当前窗口。主页和控制页在显示期间订阅共享快照，回调读取最新结果，离开时解除订阅。蓝牙连接后 PW01 不再广播，恢复过程使用保存地址直连。

## 7. 配对与多个 APP 依次绑定

PW01 同时只支持一条 BLE 连接。用户双键长按 1 秒打开约 60 秒的物理配对窗口后，多个 APP 可在剩余窗口内依次获取 Token；每次配对结束不延长硬件窗口。

`AgpLightControlService.BindAsync` 使用独立的配对流程：

1. 显示“正在连接 PW01”，启动 60 秒等待上限。
2. 按 500 ms 间隔串行尝试连接。单次连接等待最多 3 秒，给 Android 完成正常 GATT 建连的时间；500 ms 只用于两轮之间的退避，不在原生连接尚未收尾时重复发起建连。
3. 连接暂时不可用时显示“连接未完成，正在恢复蓝牙连接并自动重试”。BLE 连接错误无法单独证明存在其他手机，因此不把普通超时显示为占用提示。用户取消、离开页面或等待超时均停止重试。
4. 连接成功后显示“已连接，正在获取配对信息”。只开启 Control Point Indicate，读取能力位并保存到本地设备记录，以确认支持 Token 配对，再发送 `AUTH_GET_TOKEN`。
5. 检查成功结果及四字节 Token，将 Token 与配对阶段读取的能力位一并保存到本地设备记录。ATT Indication 接收确认由手机 BLE 栈自动完成，不新增 AGP 确认命令。
6. Token 保存成功即配对完成，关闭配对提示框并显示“添加成功”，停止扫描后通过 `//DevicesPage` 直接返回主页。不在配对连接上继续执行 `AUTH_TOKEN`、读取/订阅灯状态或校时；PW01 的预期主动断开不会把配对结果改为失败。连接清理失败也不删除已保存的 Token。
7. 绑定连接收尾后加入全局集合，重新连接并使用新 Token 认证；使用本地能力安排资料读取，只有能力缺失或明确失效时才补读。

本地配对信息是设备地址、Token 和配对时读取的能力位，设备名称、添加时间等属于列表信息。`Light State` 的开关、亮度、过渡、模式、状态标志和状态版本号只服务于运行状态与控制，不参与配对持久化。

设备设置页的“解除绑定”通过 `AgpLightControlService.RemoveDeviceAsync` 与灯控操作串行执行：先释放目标设备的 AGP 客户端、取消通知并断开目标 GATT 连接，再清理扫描缓存、状态缓存和本地设备记录（包含 Token 与配置）。必须在原生断开成功后才删除记录；失败时保留记录并提示重试。删除其他设备不影响当前控制会话，删除完成后旧页面迟到的控制或状态查询在重连前被拒绝。诊断输出 `[BLE/Removal]` 记录开始、成功或失败，Debug Timing 额外记录 `AGP.RemoveDevice` 与 `Connection.DisconnectDevice` 阶段。

删除本地设备记录不会打开 PW01 的物理配对窗口。重新添加时，仍需双键长按 1 秒，确认蓝灯闪烁后扫描配对。PW01 只有一条连接，保持连接时不会广播；因此解除绑定必须释放连接，才能恢复广播和再次扫描，无需修改固件。

重试仅覆盖建连阶段。蓝牙权限等发现错误、连接成功后的协议拒绝、无效 Token 或保存失败直接结束本次配对；窗口已关闭时提示重新开启窗口，避免不断重连占用唯一连接。Android 原生 Dialog 与其他平台的页面遮罩使用相同阶段文案，倒计时不会覆盖阶段提示。

提示框和倒计时由添加页面管理。倒计时使用页面自己的取消令牌，不能使用配对服务内部的关联令牌：服务完成并释放关联令牌源后，页面取消无法再传递给它。配对结束先停止倒计时并关闭提示框，再等待倒计时任务收尾；取消按钮和页面离开直接关闭原生 Dialog/页面遮罩，已经取消的倒计时不会继续更新界面。

## 8. 重要限制

- APP 可维护多个 PW01 GATT 连接；每台 PW01 仍只允许一部手机连接。同一手机可保持的设备数量和无线稳定性取决于手机蓝牙栈与硬件，需要在目标手机上验证。
- BLE 广播只能说明设备可能可达，不能直接表示灯的真实开关状态；真实状态仍需 GATT 读取。
- 扫描缓存是短期连接优化，不等于设备当前一定在线。
- 主页只显示已有状态及控制会话通知，未连接设备的真实状态可能未知；Toggle 由设备决定翻转方向。
- 添加页在连接绑定前停止扫描；实际发布前应在目标手机上验证直接连接、连接超时和 GATT 133 错误。

## 9. Debug 实体测试分阶段计时

Timing 仅在 Debug 构建中启用。Release 使用共享空 scope，不创建 Stopwatch 计时、AsyncLocal 上下文或操作 ID；`Mark`/`SetResult` 调用在编译时移除，响应计时探针也不编译进 Release。原有诊断日志和文件开关保持原来的行为。

Debug 启动输出 `[BLE/Test]` 环境信息（应用版本、平台、系统版本、手机型号），操作输出 `[BLE/Timing]`。两者自动进入 Visual Studio“输出 → 调试”，不需要开启隐藏调试模式。需要保存文件时，可在“我的 → 应用版本”连续点击版本号 5 次（相邻间隔不超过 2 秒），确认开启调试模式，同时启用文件输出和配置编辑入口。沿用原有日志开关的持久化值。

调试模式下，该页面的“编辑 appsettings.json”入口打开文本编辑器。`AppSettingsService` 首次读取时将应用包中的默认 JSON 复制到 `FileSystem.AppDataDirectory/appsettings.json`，之后保留用户保存的文本。当前字段为 `FirmwareUpdate.ListWorkerUrl` 和 `FirmwareUpdate.GetWorkerUrl`；保存前检查 JSON、未知字段、必填值、HTTP/HTTPS 地址及 64 KiB 大小限制，写入同目录临时文件后替换原文件。失败时保留编辑内容和原配置。`FirmwareUpdateConfiguration` 每次在线检查重新读取文件，已有服务实例无需重建；已经生成的更新候选仍使用该次检查取得的下载地址。关闭调试模式会停止文件输出、隐藏编辑入口，保存的配置继续生效。回归测试覆盖点击间隔与确认、编辑入口权限、无效配置保留、持久化，以及同一个升级服务保存后再次检查使用新地址。

页面性能还输出 `UI.Control.Construct`（页面构造总耗时）、`UI.Control.CreateViews`（页面 XAML 框架创建）、`UI.Control.LoadCapabilityViews`（能力确认后各个 `LazyView` 的首次加载）、`UI.Control.Preload`（主页预加载）、`UI.Control.RoutePage`（路由获取及是否命中预加载）、`UI.Home.NavigateControl`（导航）、`UI.Control.Entrance`（短动画）、`UI.Control.BleAfterFirstFrame`（首帧后的扫描清理与连接）及 `UI.Control.AfterNavigation`（内容加载、BLE 与动画全部结束）。能力相关区域使用 CommunityToolkit.Maui 的 `LazyView<T>`；只有设备支持并需要显示时才调用 `LoadViewAsync`，不支持的区域不会创建内部视图。特效参数弹层在首次打开参数设置时才加载。上述阶段同样仅在 Debug 启用，动画 120 ms 是目标时长，不代表创建、布局、导航和设备连接总共只需要 120 ms。

每行 Timing 包含：

- `id`：一次操作的关联 ID，嵌套异步阶段共用；后台状态查询通常拥有自己的 ID。
- `span` / `parent`：阶段及其父阶段，用于区分包含关系。
- `stage`：阶段名称；`event=start/mark/end` 表示开始、关键点和结束。
- `elapsed`：当前阶段耗时；`total`：从该关联操作开始算起的毫秒数，均使用单调时钟。
- `result`：完成、复用、协议结果、取消或异常类型；异常在进入内部阶段前发生时，父阶段可能只输出结束，具体结果见子阶段及原有错误日志。

首次主页开关的总时间查看 `UI.Home.Power` 的 `event=end`；进入控制页的初始化时间查看 `UI.Control.Appearing` 和 `UI.Control.Initialize`。主要分段如下：

| stage | 含义 |
| --- | --- |
| `UI.Home.StopStatusRefresh` | 取消后台状态查询并等待查询和断开收尾 |
| `AGP.Operation.Lock` / `Connection.LockWait` | 业务锁和连接/GATT 锁的排队时间 |
| `Connection.FindDevice` | 缓存命中或按保存的地址直接连接 |
| `Connection.NativeConnect` | 原生 BLE 建连请求到返回 |
| `GATT.GetServices` / `GATT.GetCharacteristics` | 服务和特征 API 耗时，可能命中已有缓存 |
| `GATT.NativeStartUpdates` | 各特征的通知/Indicate 订阅，包含 CCCD 写入 |
| `AGP.ReadCapabilities` / `AGP.TokenLookup` | 读取能力及本地凭据查询，不输出 Token 正文 |
| `AGP.Authenticate` | 认证命令到客户端拿到协议结果 |
| `AGP.ReadLightState.Initial` | 初始化时读取灯状态；缓存复用会另有标记 |
| `AGP.Profile.GetEffect` | 控制页补充读取特效参数 |
| `UI.Control.LoadCapabilityViews` | 根据已读取的能力调用各个 `LazyView.LoadViewAsync`；不支持的模块不会加载内部视图 |
| `AGP.Command.OnOff` | 开关命令到客户端拿到协议结果 |
| `GATT.NativeWrite` | 原生 GATT 写入请求到写回调完成 |
| `responseReceived` 标记 | 收到响应时的请求 TID、请求/响应 opcode、请求到响应到达的耗时 |

`responseReceived` 使用发送时捕获的上下文，即使原生回调没有继承 AsyncLocal，也可以对应到原操作。它记录响应到达，业务包验证和成功判定仍由原 AGP 客户端负责。响应可能早于 GATT 写入回调，因此应同时查看 `GATT.NativeWrite` 和 `AGP.Authenticate` / `AGP.Command.OnOff`。

父阶段包含子阶段的时间，不能把所有行的 `elapsed` 相加。后台查询取消后的断开通常保留原后台查询 ID，可以用时间戳与 `UI.Home.StopStatusRefresh` 对齐。APP 的成功响应时间也不等于光学测量的 LED 点亮时间。

首轮测试保持当前 PW01 固件和广播策略：

1. 用实体按键将主 LED 关闭，停止 APP。
2. 先清空 Visual Studio 输出，再以 Debug 启动 APP；保留 `[BLE/Test]` 和随后全部 BLE 输出。
3. 在主页直接点击一次开关，将主 LED 打开；无需等待硬件状态查询。
4. 等 LED 点亮和 `UI.Home.Power event=end` 输出完成，保存启动至该操作结束的日志。保留 Timing、BLE/TX、BLE/RX、Connection、Capabilities 和错误信息，以便核对直接连接、认证、Toggle 和最终状态通知的完整过程。

开关使用支持 `ONOFF_SET=2` 的 PW01 固件；配对流程将单轮 Android 建连窗口与 500 ms 轮间退避分开，避免应用主动取消正常建连。若需要进一步测量实际连接间隔和固件执行时刻，再通过独立 UART 日志进行第二轮验证。

控制页导航另有 Android Debug 专用 `[UI/Timing]` 输出。整个观察器及调用均用 `#if DEBUG && ANDROID` 隔离，Release 不包含观察器、事件订阅、Stopwatch 或这些日志。每次有效点击有独立 `navigation` 编号，`sinceTap` 从点击处理开始计算（不是手指按下时间），用于跨页面事件对齐：

| 阶段 | 用途 |
| --- | --- |
| `TapAccepted`、`RoutePageReady`、`GoToAsync.Returned` | 点击接收、预加载页面取出、导航任务返回 |
| `Appearing.Enter/Exit`、`NavigatedTo.Enter/AfterBase/Exit` | 区分页面事件到达及基类调用耗时 |
| `Dispatcher.Queued/Executing` | `queueWait` 是初始化任务等待界面线程执行的时间 |
| `Page.HandlerChanging/Changed`、`HandlerWindow`、`HandlerSummary` | 原生 Handler 相关事件区间及控件类型汇总；事件区间可能嵌套，且不覆盖所有创建工作，不能直接相加 |
| `Page.SizeAllocated`、`Native.GlobalLayout` | 页面尺寸回调及布局完成观察点，不等同于整个布局耗时 |
| `Native.FirstPreDraw`、`Native.FirstDrawCallback`、`Native.AfterDrawPosted` | 原生视图首次绘制前、绘制观察回调、其后界面队列执行点；均不保证像素已呈现到屏幕 |
| `Android.WindowFrame` | Android 7/API 24 起可用，窗口帧的 `layoutMeasure`、`draw`、`total`；可能包含主页和过渡帧，callbackSinceTap 记录采样回调到达时间，汇总输出的 sinceTap 不等于帧开始时间 |
| `AfterNavigation.Finished`、`Page.Left`、`Summary` | 初始化完成或离开页面时解除观察器，并输出汇总 |

限制尺寸日志最多 4 次、布局日志最多 2 次；窗口帧最多采集 64 次，汇总时输出前 6 帧和后续慢帧（measure ≥ 16 ms 或 total ≥ 32 ms），覆盖较晚加载的预设模块；控件事件覆盖路由已有控件、首帧后 LazyView 以及 CollectionView 动态模板，按模块和控件类型汇总。MeasureOverride/ArrangeOverride 的耗时先积累后输出，避免每次测量直接打印影响布局。新增 `[UI/Timing]` 阶段如下：

| 阶段 | 用途 |
| --- | --- |
| `Home.BeforeNavigation.CancelPreload/LeasePromotion` | 停止预加载、升级租约的调用耗时 |
| `Home.BeforeNavigation.LeaseLockWait/LeaseUpgradeAndCancel` | 租约锁等待及升级、请求取消租约的耗时 |
| `Home.BeforeNavigation.CancelRequest/QueueLockWait/QueueClear` | 主页查询取消请求、待查询队列锁等待及清空队列 |
| `Home.BeforeNavigation.LogOutput` | 已有调试输出耗时与计时报告输出耗时；各操作的 `loggingIncluded` 已包含在其 `elapsed` 中 |
| `Home.StatusRefresh.CancelCallbacks` / `Connection.Lease.CancelCallbacks` | CancelAsync 同步请求时间，以及线程池排队加取消回调完成时间；后者不阻塞导航 |
| `FirstFrame.WorkReleased` | 首次绘制回调之后的工作启动点；不等同于显示器呈现确认 |
| `LazyViewCreation` | 每个模块的 XAML 创建、绑定和 Content 赋值耗时 |
| `HandlerSummary` | 每个 LazyView 内部各控件 HandlerChanging → Changed 的次数、总区间与最大区间，包含预设列表动态生成的 Border、Button |
| `LayoutSummary` | 各 LazyView，以及预设 CollectionView、Border、Button 的 Measure/Arrange 次数、包含子控件的总耗时与单次最大值 |

首帧之前只套用本地能力、状态和配置；保留已有布局与 LazyView 占位。Android 通过页面原生 OnDraw 后的 Post 作为门控。首帧之后逐个创建支持模块，每个模块加入后等下一轮绘制再继续；创建仍在 UI 线程。扫描停止和 AGP 控制资料请求在后台发起，其完成后仅将状态应用回 UI，不等待全部模块创建。已有本地能力时内容路径也不等待 BLE；旧记录缺少能力时，待控制资料补充能力后才创建相应模块。离开页面会取消未加载模块及页面对 BLE 准备的等待，共享准备继续。

父子 Handler 区间、Measure/Arrange 区间可能嵌套，不能相加当成总耗时。Release 不包含以上新计时器、统计或诊断订阅；Release 仍保留用于分批加载的首帧/绘制门控，这属于实际调度逻辑。

原有 `[BLE/Timing]` 继续测量动画、扫描收尾和 AGP 初始化。实体测试请清空输出，以 Debug 从主页单击进入控制页，等待初始化结束后保存完整输出；至少保留 `[UI/Timing]`、`[BLE/Timing]` 和 Android 的丢帧/GC 日志。建议再返回主页重复进入一次，用于比较首次与后续进入。
